## Dérogations

### DER-001 — `'unsafe-eval'` dans `script-src` (Exigence 15.5)

| Champ | Valeur |
|---|---|
| Directive | `script-src` (nginx `nginx/conf.d/partipolia.conf` et `app/core/middleware.py`) |
| Valeur dérogatoire | `'unsafe-eval'` (accompagné de `'unsafe-inline'`) |
| Bibliothèque | Alpine.js 3.x (`app/static/js/alpine.min.js`, build standard) |
| État | Dérogation maintenue |

Essai du build CSP (`@alpinejs/csp`) : ce build n'évalue pas de chaînes
JavaScript et n'accepte que des références à des composants enregistrés via
`Alpine.data(...)`. Les gabarits actuels reposent sur des expressions inline que
ce build ne sait pas interpréter :

- objets et méthodes inline dans `x-data` (`app/templates/login.html`,
  `app/templates/public/login.html`, `app/templates/public/base.html`) ;
- expressions composées dans `x-text`, `x-show`, `:class`, `@click` et
  `@submit.prevent` (ternaires, concaténations, appels avec arguments, négations)
  dans `public/simulator.html`, `public/join.html` et d'autres pages.

Les retirer exige de réécrire ces gabarits en composants `Alpine.data` avec
propriétés et méthodes sans argument, sans risque de régression visuelle
acceptable dans le périmètre de cette tâche.

Justification : la surface d'attaque est limitée car (1) toutes les ressources
sont servies depuis `'self'`, `connect-src 'self'`, `frame-ancestors 'none'`,
`base-uri 'self'` et `form-action 'self'` restent restrictifs ; (2) les
expressions Alpine sont écrites côté serveur, et les données utilisateur sont
échappées par Jinja2 (auto-échappement) et injectées en JSON via `tojson`.

Remédiation prévue : migrer les gabarits vers des composants `Alpine.data`,
passer à `@alpinejs/csp`, puis retirer `'unsafe-eval'` des deux emplacements.
Une fois retiré, le test `tests/unit/test_middleware.py` pourra l'imposer.
